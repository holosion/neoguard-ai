# NeoGuard revision B — verification record

Date: **21 October 2026**. Native tools: **KiCad 10.0.4**. This record describes checks actually performed on the current revision B files. It does not establish assembled-hardware operation or manufacturing approval.

## Schematic - checked

Native KiCad reads and exports the two-sheet project. The PDF contains the ESP32-S3 system connections and a separate power/carrier-harness page. `ERC.json` reports **0 violations** across both sheets, with error and warning severities included.

Independent comparison of `NeoGuard.net.xml` with the carrier manifest found **0 mismatches** across **26 carrier components, 99 carrier pins and 31 intended nets**. There are **98 connected carrier pins** and **1 deliberate no-connect: J2.5**. Every J1 pin preserves its defined function.

U1 has **20 logical pins**: 18 used GPIOs, controller 3V3 output and GND. All were independently checked against the expected net names. U1 has no PCB footprint and is excluded from the board. Its identifiers are logical GPIO/function names, not physical development-board header positions. U1 3V3 joins **DEV3V3**, not selected **V3V3**; JP1 is preserved without a bypass.

GPIO4/5 visibly branch to both I2C sensors. The RTC, TFT, SD, RGB resistor channels and transistor buzzer driver have individual drawn signal paths. The PDF was rendered and visually reviewed; signal labels were moved away from pin names/numbers. `ESP32-connections.csv` lists U1 functions separately from the 72 connector/selector entries in `Wiring.csv`.

## PCB and ground copper - checked

The native board is **140 x 105 mm**, with **two copper layers**, four 3.2 mm unplated M3 mounting holes, 26 electrical footprints and four mounting-hole footprints. An independent native pcbnew read found **0 mismatches across all 99 carrier pads**. J2.5 has its isolated no-connect net. U1 is absent from the carrier PCB.

All **50 non-ground routing connections** completed. Ground uses native-filled F.Cu/B.Cu zones and **75 GND stitching vias**. The ground zones cover approximately **12,214.11 mm2 on F.Cu** and **13,408.50 mm2 on B.Cu**. Both zones use thermal pad connections and remove isolated islands. Some signal/power crossings remain on B.Cu, so it is not an uninterrupted dedicated plane.

Zone clearance is **0.25 mm**; thermal relief gap/spoke is **0.30/0.40 mm**. Track widths are **0.30 mm signal / 0.60 mm power**, with **0.80/0.40 mm vias**. Read-back project rules retain **0.25 mm copper clearance**, **0.30 mm minimum track**, **0.50 mm copper-to-edge clearance** and **0.15 mm silkscreen clearance**.

`pcb_drc.json`, generated by native KiCad with schematic parity and error/warning severities included, reports **0 violations, 0 unconnected items and 0 schematic-parity issues**. Native 3D and copper-layer exports were visually reviewed. Reproducible independent checks are in `verify_revision_b.py`, with results in `verification_summary.json`.

Reports retain their own `ignored_checks` metadata. Default ignored categories, such as footprint-filter checks, missing courtyards and track endpoints not centred on vias, are not claimed as tested by a report that ignores them. No new error exclusions were added to hide failures.

## Physical checks — not performed

No board has been fabricated, assembled, powered or flashed as part of this design task. The following remain unverified:

- Actual ESP32-S3 development-board physical header layout. J1 is a functional cable connector, not a devboard socket.
- Module connector order, actual breakout power/logic compatibility, backlight requirements and purchased-part dimensions/pinouts.
- Regulator/supply current budget, loaded-rail stability, harness voltage drop, reverse-polarity handling and simultaneous-power behaviour.
- Buzzer load current, Q1 saturation, actual LED polarity/lead order, RTC battery condition and disabled charging.
- Mechanical/enclosure fit, module mounting, assembly tolerances and a manufacturer-specific DFM review.
- Sensor accuracy, integrated display operation, firmware timing, SD logging and end-to-end authenticated backend transfer.

The prior isolated ST7789 display test was recorded as working in the existing project documentation. The blank integrated-screen issue remains an unconfirmed integration fault; the carrier design is not evidence that it is resolved. This prototype includes no medical isolation, patient-protection circuit or clinical validation.
